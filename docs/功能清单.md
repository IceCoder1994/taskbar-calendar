## 0. 产品定位与设计原则

**定位**：点击任务栏右下角时钟时，弹出本插件的日历面板，替代 Windows 原生日历弹窗。

**设计原则**：

1. 保留原生时钟显示，通过透明覆盖层劫持点击，外观零改动。
2. 不使用全局鼠标钩子，规避杀软误报与输入链路风险。
3. 只替换"点击时钟弹日历"行为；通知中心（铃铛 / Win+N）照常可用。
4. 定位失败可降级、可手动校准，保证异常场景可用。

**已知边界（通知中心与日历的关系）**：

1. Win11 中通知中心与日历属于同一个系统浮出面板（点时钟、点铃铛、Win+N 打开的都是它）；24H2 起以通知为主，日历默认收起在面板底部。
2. 点时钟路径被覆盖层接管后，系统日历 100% 不出现；通知中心仍可从铃铛 / Win+N 正常打开，通知功能完整保留。
3. 通知中心面板底部的系统日历区，系统未提供单独移除的开关：默认收起时不显示，手动展开后展开状态会被系统记忆。

## 1. 核心交互

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F-01 | 点击时钟弹出日历 | 透明覆盖层劫持左键，原生日历不弹出 | P0 |
| F-02 | 收起面板 | 再次点击时钟 / Esc / 失焦 / 点击面板外 | P0 |
| F-03 | 时钟区域自动定位 | UI Automation 多级兜底（类名+名称校验 / 名称特征+位置 / 类名兜底），失败时回退手动校准位置 | P0 |
| F-04 | 覆盖层置顶保持 | 开始菜单、Alt+Tab、全屏应用、explorer 重启后不失效 | P0 |
| F-05 | 不影响原生功能 | 通知中心（铃铛 / Win+N）照常弹出；点时钟不再弹系统日历；原生时钟显示不变 | P0 |
| F-06 | 右键时钟菜单 | 精简菜单：打开日历 / 设置 / 退出 | P2 |
| F-07 | 面板位置自适应 | 时钟正上方右对齐，屏幕边缘自动 clamp | P1 |

## 7. 明确不做（本期）

| 功能 | 原因 |
|---|---|
| 日程 / 待办 / 提醒 | 二期评估 |
| 同步系统日历 / Outlook | 接口受限、工作量大 |
| 自定义渲染时钟（时钟显示农历） | 已选保留原生时钟方案 |
| 多显示器任务栏时钟 | 当前单屏；架构预留扩展 |
| Windows 10 支持 | 任务栏结构不同，仅适配 Win11 |
| 天气、黄历宜忌 | 二期评估 |

## 8. 统计与执行前提

- 功能项合计 **33** 项：P0 五项、P1 十四项、P2 十四项；本期不做 6 项。
- 执行前提：安装 .NET 8 SDK（`winget install Microsoft.DotNet.SDK.8`）。
- 实施顺序：P0 骨架 → P1 核心链路验证 → P2 日历 UI → P3 托盘 / 设置 / 自启 → P4 打磨验证。
